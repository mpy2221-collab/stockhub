# StockHub 기획서

사내·매장 창고의 **현재고**와 **입출고**를 관리하는 웹 시스템이다.  
Spring Framework를 쓰지 않고 Servlet 4.0 + JSP + MyBatis로 구현한다.

관련 문서: [요구사항 정의서](요구사항정의서.md), [기능 명세서](기능명세서.md), [시스템 아키텍처](시스템아키텍처.md), [ERD](ERD.md), [테이블 정의서](테이블정의서.md)

---

## 1. 배경과 목표

창고가 여러 곳이면 품목 전체 수량만 보면 어디 재고인지 알 수 없다.  
StockHub는 **창고 × 품목**을 재고의 최소 단위로 두고, 실제 수량 변동만 이력으로 남긴다.

| 목표 | 내용 |
|---|---|
| 현재고 | 창고별 수량 조회. 품목 전체 = 창고 합계 |
| 입출고 | 입고·출고·이동·조정을 한 트랜잭션으로 처리하고 이력에 남긴다 |
| 요청 | 일반 회원은 입고·출고를 요청만 한다. 재고는 관리자 승인 후에만 변한다 |
| 현황 | 안전재고 미달·대기 요청·입출고 추이를 대시보드에서 본다 |
| 기준 정보 | 품목·창고·카테고리·회원을 관리자가 관리한다 |
| 보조 | 품목코드 바코드, 입출고 엑셀 다운로드, 대표 이미지 1장 |

---

## 2. 사용자

가입 기본 등급은 **일반(3)**이다. **관리자(1)**는 관리자 화면에서만 지정한다.

| 구분 | 하는 일 |
|---|---|
| 비로그인 | 로그인, 회원가입(이메일 인증), 비밀번호 찾기 |
| 일반 회원 | 재고 조회, 품목 상세·바코드, 입고·출고 요청, 내 요청, 마이페이지 |
| 관리자 | 일반 회원 조회 기능 + 대시보드, 기준 정보 CRUD, 입고/출고/이동/조정, 요청 승인·거절, 회원 등급, 엑셀 |

관리자는 회원 화면에서 입출고 요청·내 요청 메뉴를 쓰지 않는다. 재고 처리는 `/admin/*`에서만 한다.

---

## 3. 범위

- 회원: 가입(이메일 인증번호), 로그인/로그아웃, 마이페이지(정보·비밀번호·탈퇴)
- 재고 조회: 창고·카테고리·키워드·부족 필터, 품목 상세, 바코드
- 일반 회원 요청: 입고·출고 요청, 본인 요청 목록
- 관리자 재고 처리: 입고, 출고, 창고 이동, 재고 조정, 입출고 이력
- 요청 승인·거절 (출고 승인 시 재고 부족이면 실패, WAIT 유지)
- 대시보드: 카드·차트·표
- 메인 홈: 로그인 후 요약 포털
- 품목 대표 이미지 1장 (`tb_goods.image_path`, 파일은 `C:/Temp/stock`)
- 기간별 입출고 엑셀 다운로드
- 좁은 화면: 햄버거 서랍, 표 가로 스크롤

## 4. 핵심 도메인 규칙

재고 수량의 기준은 `tb_warehouse_stock`(창고×품목)이다.  
`tb_stock_request`는 요청만 담당하고, 이 테이블에서 재고를 직접 바꾸지 않는다.  
실제 수량 변동만 `tb_stock_history`에 남긴다. `history_type`은 `IN` / `OUT` / `ADJUST`만 쓴다.

| 작업 | 재고 | 이력 |
|---|---|---|
| 입고 IN | 해당 창고 + | 1행 |
| 출고 OUT | 해당 창고 수량 ≥ 요청 수량일 때만 − | 1행 |
| 조정 ADJUST | 한 창고 수량을 목표값으로 | 1행 |
| 이동 | 출발 창고 −, 도착 창고 +. 출발 부족이면 전체 롤백 | 화면 1건, DB는 같은 `group_no`의 OUT+IN 2행 |

입고 요청: WAIT → 승인 시 재고 증가 + IN / 거절 시 REJECT, 재고 유지.  
출고 요청: WAIT → 승인 시 재고 감소 + OUT / 거절 시 REJECT, 재고 유지. 부족하면 실패하고 WAIT를 유지한다.  
안전재고(`safety_qty`)는 **전 창고 합계** 기준이다.

상세 컬럼·관계는 [ERD](ERD.md), [테이블 정의서](테이블정의서.md)를 따른다.

## 5. 기술 스택

| 구분 | 선택 |
|---|---|
| 언어 | Java 11 |
| 프로젝트 | Maven war |
| 서버 | Apache Tomcat 9 (로컬 개발 8070, 배포 8080) |
| 웹 | Servlet 4.0 (`javax.servlet`) + JSP, JSTL, EL |
| 프론트 | jQuery, CSS, Chart.js, JsBarcode |
| JSON | Gson |
| 엑셀 | Apache POI |
| DB | Oracle XE, 1521 / 계정 `stock_user` |
| 매퍼 | MyBatis (Spring 없음) |
| JDBC | ojdbc8 |
| 인증 | HttpSession 30분, jBCrypt |
| 가드 | EncodingFilter, LoginFilter, AdminFilter |
| 메일 | Google SMTP + JavaMail. Spring 메일 아님 |
| 파일 | Servlet Part, `C:/Temp/stock` |
| 테스트 | JUnit 5 + Mockito |
| 개발 | Cursor AI, MCP |

기본 패키지: `kr.inventory`  
세션 키: `loginMember` (저장 전 `memberPw`는 null)

구현과 문서 작성은 **Cursor AI**를 쓴다.  
**MCP(Model Context Protocol)**로 GitHub(브랜치·PR·머지), Playwright(화면 확인), Sequential Thinking(규칙 정리), Notion Toolbox(기획 초안), Context7(라이브러리 문서)을 편집기에 붙여 사용한다.  
요구사항과 재고 규칙은 사람이 정하고, Cursor는 그 규칙에 맞춰 Servlet·JSP·MyBatis 코드와 보고서를 작성한다.

## 6. 화면 구성

**진입:** 비로그인은 로그인 화면이 첫 화면이다. `/home`은 로그인 후에만 연다.

**헤더:** 로고, 로그인 시 마이페이지·(관리자면)관리자페이지·이름·로그아웃. 비로그인은 로그인/회원가입. 기능 메뉴는 헤더에 두지 않는다.

**회원 사이드바** (`/admin/*`가 아닌 화면)

| 대상 | 메뉴 |
|---|---|
| 비로그인 | 홈 |
| 일반 회원 | 홈, 재고 조회, 입출고 요청, 내 요청 |
| 관리자 | 홈, 재고 조회 |

**관리자 사이드바** (`/admin/*`)

| 구역 | 메뉴 |
|---|---|
| 현황 | 재고 현황 |
| 기준 정보 | 품목 관리, 창고 관리, 카테고리 관리, 회원 관리 |
| 재고 처리 | 입고 처리, 출고 처리, 창고 이동, 재고 조정, 입출고 이력 |
| 요청 | 요청 승인 |

960px 미만에서는 사이드바를 접고 햄버거 서랍으로 연다. 표는 칸을 억지로 줄이지 않고 가로 스크롤한다.

## 7. 구현 순서

1. 프로젝트 구축, DB, 회원(가입/로그인/마이페이지)
2. 창고·품목·카테고리, 재고 조회
3. 입고/출고/이동/조정 + 단위 테스트
4. 입고·출고 요청·승인
5. 공통 레이아웃(사이드바)
6. 메일(가입 인증, 임시 비밀번호, 요청 결과)
7. 품목 대표 이미지
8. 대시보드, 메인 홈
9. 엑셀·바코드
10. 좁은 화면 레이아웃

---

## 8. 제약

- SQL·트랜잭션은 Service. Servlet은 화면 이동과 JSON만.
- Dao는 MyBatis mapper 호출만. `PreparedStatement` 직접 사용 금지.
- 이력 유형은 `IN` / `OUT` / `ADJUST`만. 이동을 별도 유형으로 두지 않는다.
- 인증번호는 세션에만 둔다. 인증 테이블은 없다.
- 요청 승인·거절 메일이 실패해도 처리 결과는 되돌리지 않는다.
- 마지막 관리자(등급 1이 1명)는 탈퇴·등급 하향을 할 수 없다.
