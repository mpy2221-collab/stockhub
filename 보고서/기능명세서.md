# StockHub 기능 명세서

기준: [기획서](기획서.md), [요구사항 정의서](요구사항정의서.md).  
데이터는 [ERD](ERD.md), [테이블 정의서](테이블정의서.md).  
계층·URL 배치는 [시스템 아키텍처](시스템아키텍처.md).

화면은 `/WEB-INF/views/` JSP. Ajax는 JSP 없이 Gson JSON만 응답한다.  
SQL·트랜잭션은 Service. Servlet은 파라미터 수집·화면 이동·JSON만.

## 1. 인증 · 회원

### 1.1 로그인

| 항목 | 내용 |
|---|---|
| URL | GET `/loginFrm`, POST `/login` |
| 권한 | 비로그인 |
| 입력 | 아이디, 비밀번호 |
| 처리 | `MemberService`에서 BCrypt 검증. 성공 시 세션 `loginMember`(비밀번호 null), `/home` |
| 실패 | 아이디 없음·비밀번호 불일치. 모달 안내 후 로그인 화면 유지 |

비로그인이 `/` 또는 `/home`을 열면 `/loginFrm`으로 보낸다.

### 1.2 회원가입

| 항목 | 내용 |
|---|---|
| URL | GET `/joinFrm`, POST `/join` |
| Ajax | `/checkId`, `/checkEmail`, `/sendEmailCode`, `/verifyEmailCode` |
| 권한 | 비로그인 |
| 입력 | 아이디, 비밀번호, 이름, 이메일, (전화·주소) |
| 처리 | 이메일 인증을 통과한 세션만 `/join` 허용. 등급 3으로 `tb_member` insert |
| 규칙 | 아이디·이메일 중복 불가. 인증번호 6자리, 세션 만료 5분. 인증 테이블 없음 |

### 1.3 비밀번호 찾기

| 항목 | 내용 |
|---|---|
| URL | GET `/searchPwFrm`, POST `/searchPw` |
| 입력 | 아이디, 이메일 |
| 처리 | 둘 다 맞으면 임시 비밀번호를 BCrypt로 저장하고 메일 발송 |
| 실패 | 불일치 시 메일을 보내지 않음. 안내만 |

### 1.4 마이페이지

| 항목 | 내용 |
|---|---|
| URL | GET `/mypage`, POST `/updateMember`, POST `/updatePw`, POST `/withdraw` |
| 권한 | 로그인 |
| 조회 | 본인 정보. 아이디·이메일은 읽기 전용 |
| 정보 수정 | 이름·전화·주소 |
| 비밀번호 변경 | 현재 비밀번호 확인 후 새 비밀번호 |
| 탈퇴 | 확인 모달 → 현재 비밀번호. 맞으면 `tb_member` 행 삭제, 세션 종료, `/loginFrm` |
| 탈퇴 제약 | 마지막 관리자(등급 1이 1명)는 실패. 이력·요청의 `member_id` 문자열은 그대로 둠 |

### 1.5 로그아웃

GET `/logout`. 세션 무효화 후 로그인 화면.

## 5. 관리자 — 현황

### 5.1 대시보드

| 항목 | 내용 |
|---|---|
| URL | GET `/admin/dashboard` |
| Ajax | GET `/admin/dashboard/chart` (Gson JSON) |
| 권한 | 관리자 |

**카드**

- 기존: 품목, 창고, 카테고리, 회원 수
- 추가: 총 재고(사용 중 품목의 전 창고 `stock_qty` 합), 안전재고 미달 건수, 오늘 입출고 수량, 이번달 입출고 수량, 대기 요청 건수
- 오늘·이번달 입출고는 `tb_stock_history`의 `IN`+`OUT` **qty 합**. `ADJUST`는 넣지 않는다
- 총 재고·미달은 `use_yn = 'Y'` 품목만

**차트 (Chart.js)**

- 월별 입출고 추이
- 창고별 재고
- 카테고리 비율
- 출고 상위 품목

**표**

- 미달 목록: 코드, 품목명, 합계, 안전재고 → `/goods/view`
- 최근 이력 10건: 일시, 유형, 품목, 창고, 수량
- 대기 요청: 요청 승인 화면으로 연결

## 7. 관리자 — 재고 처리

공통: 한 `SqlSession`에서 재고 변경 + 이력 insert. 실패 시 rollback.

### 7.1 입고

| 항목 | 내용 |
|---|---|
| URL | `/admin/stock/inFrm`, POST `/admin/stock/in` |
| 처리 | 해당 창고 `stock_qty` +. 없으면 행 생성 후 증가 |
| 이력 | `history_type=IN` 1행. before/after는 그 창고 수량 |

### 7.2 출고

| 항목 | 내용 |
|---|---|
| URL | `/admin/stock/outFrm`, POST `/admin/stock/out` |
| 처리 | 해당 창고 수량 ≥ qty일 때만 − |
| 실패 | 부족·행 없음. 재고·이력 변경 없음 |
| 이력 | `history_type=OUT` 1행 |

### 7.3 창고 이동

| 항목 | 내용 |
|---|---|
| URL | `/admin/stock/moveFrm`, POST `/admin/stock/move` |
| 입력 | 품목, 출발 창고, 도착 창고, 수량 |
| 처리 | 출발 OUT + 도착 IN. 같은 `group_no`. 한 트랜잭션 |
| 실패 | 출발 부족이거나 출발=도착이면 전체 롤백 |
| 화면 | “창고 이동” 한 건. 이력에서는 OUT·IN 두 행 |

### 7.4 재고 조정

| 항목 | 내용 |
|---|---|
| URL | `/admin/stock/adjustFrm`, POST `/admin/stock/adjust` |
| 처리 | 한 창고 수량을 목표값으로 맞춤. 증가·감소 모두 가능 |
| 이력 | `history_type=ADJUST` 1행. qty는 변동량 |

### 7.5 입출고 이력

| 항목 | 내용 |
|---|---|
| URL | GET `/admin/stock/history` |
| 필터 | 유형, 기간, 품목, 창고 |
| 표시 | 일시, 유형, 품목, 창고, 수량, before/after, 처리자, 메모 |
| 이동 | 같은 `group_no` 두 행으로 출발 출고·도착 입고를 같이 봄 |

### 7.6 엑셀

| 항목 | 내용 |
|---|---|
| URL | `/admin/excel` |
| 권한 | 관리자 |
| 처리 | 기간별 입출고 이력을 Apache POI로 xlsx 다운로드 |
| 비고 | 업로드(일괄 등록)는 범위 밖 |

## 8. 관리자 — 요청 승인

| 항목 | 내용 |
|---|---|
| URL | GET `/admin/stock/request`, POST 승인/거절 Ajax |
| 권한 | 관리자 |
| 기본 | `status` 없거나 빈 값이면 WAIT. 대기 탭이 기본 |
| 목록 | 요청번호, 유형, 요청자, 품목, 창고, 수량, 상태, 일시. 메모 열은 두지 않음 |
| 상세 | 행 클릭 모달. 메모·처리자·처리일시 |
| 승인 | WAIT만. IN이면 재고+·history IN, OUT이면 재고−·history OUT. `request_no` 넣음. 상태 APPROVE |
| 출고 부족 | 실패. WAIT 유지. 모달 안내 |
| 거절 | WAIT만. REJECT. 재고 유지 |
| 메일 | 처리 후 요청자 이메일. 메일 실패는 commit을 되돌리지 않음 |

## 9. 공통 UI

### 9.1 레이아웃

- 헤더: 로고(`/home` 또는 비로그인 `/loginFrm`), 계정 링크. 기능 메뉴 없음
- 회원 사이드바: 홈, 재고 조회, (일반만) 입출고 요청·내 요청
- 관리자 사이드바: 현황 / 기준 정보 / 재고 처리 / 요청 구역
- 로그인·가입·비밀번호 찾기: 사이드바 없음(`no-side`)

### 9.2 좁은 화면 (960px 미만)

- 헤더: 로고 + 햄버거
- 사이드바·계정 링크는 왼쪽 서랍
- 표: 짧은 칸 `nowrap`, 긴 칸 말줄임. `.table-wrap` 가로 스크롤
- 카드·차트·필터: 1열

### 9.3 Ajax 목록

| URL | 용도 |
|---|---|
| `/checkId` | 아이디 중복 |
| `/checkEmail` | 이메일 중복 |
| `/sendEmailCode` | 인증번호 발송 |
| `/verifyEmailCode` | 인증번호 확인 |
| `/admin/dashboard/chart` | 대시보드 차트 JSON |
| 요청 승인/거절 | 관리자 요청 처리 |
| 창고별 재고 조회 | 출고·이동 화면 등 |

알림은 공통 모달(`StockModal`). 탈퇴 등 파괴 작업은 확인(취소/확인) 모달.

## 11. 단위 테스트 (Service)

Dao는 Mock. 결과는 `test-result/result-yyyyMMddHHmmss.md`에 PASS/FAIL로 기록한다.

| 영역 | 검증 |
|---|---|
| 회원 | 로그인 성공/실패, 아이디 중복, 이메일 미인증 가입 실패, 비밀번호 찾기 |
| 입고 | 해당 창고 수량 증가 |
| 출고 | 부족이면 실패, 재고 유지 |
| 이동 | OUT+IN 2행·같은 group_no·한 트랜잭션. 출발 부족이면 롤백 |
| 요청 | 입고 승인 시 IN, 출고 승인 시 OUT, 거절 시 재고 유지. 출고 부족이면 WAIT |
| 안전재고 | 전 창고 합계 < safety_qty 목록 |
| 탈퇴 | 비밀번호 확인, 마지막 관리자 불가 |
