# StockHub 시스템 아키텍처

기준: [기획서](기획서.md), [기능 명세서](기능명세서.md).  
테이블은 [ERD](ERD.md), [테이블 정의서](테이블정의서.md).

Spring 없음. Servlet 4.0 + JSP + MyBatis + Oracle.

---

## 1. 개요

브라우저 요청은 Filter로 인코딩·로그인·관리자 권한을 검사한 뒤 Servlet이 받는다.  
업무 규칙과 트랜잭션은 Service, SQL은 MyBatis Dao, 화면은 JSP 또는 Gson JSON이다.

```
요청
  → EncodingFilter (UTF-8)
  → LoginFilter / AdminFilter
  → Servlet
       → Service  ← JUnit 5 + Mockito (Dao Mock)
            → Dao (MyBatis mapper) → Oracle
       → JSP  (화면)
       → Gson (Ajax JSON)
```

재고의 기준은 `tb_warehouse_stock`(창고×품목)이다.  
요청은 `tb_stock_request`, 실제 수량 변동만 `tb_stock_history`에 남긴다.

## 2. 논리 계층

| 계층 | 역할 | 위치 |
|---|---|---|
| Presentation | URL 매핑, 파라미터, forward/redirect, JSON | `kr.inventory.*.servlet`, JSP |
| Filter | UTF-8, 로그인, 관리자 | `kr.inventory.filter` |
| Application | 재고 규칙, 트랜잭션, 메일, 엑셀 | `kr.inventory.*.service`, `common` |
| Persistence | mapper 호출만 | `kr.inventory.*.dao`, `resources/mapper` |
| Database | 7개 테이블, 시퀀스 | Oracle XE |

Servlet에 SQL을 두지 않는다. Dao에서 `PreparedStatement`를 직접 쓰지 않는다. namespace는 Dao FQCN, 바인딩은 `#{}`만.

## 4. 요청 처리 흐름

### 4.1 화면 요청 (예: 재고 목록)

```
브라우저 GET /goods/list
  → EncodingFilter
  → LoginFilter (세션 loginMember 없으면 /loginFrm)
  → GoodsListServlet
       → GoodsService.selectList(...)
            → GoodsDao (MyBatis) → tb_goods, tb_warehouse_stock
       → request.setAttribute
       → /WEB-INF/views/goods/list.jsp
```

### 4.2 Ajax (예: 아이디 중복)

```
GET /checkId?memberId=...
  → CheckIdServlet
       → MemberService.isDuplicated
       → response JSON (Gson). JSP 없음
```

### 4.3 재고 변경 (예: 창고 이동)

```
POST /admin/stock/move
  → AdminFilter (등급 1)
  → MoveServlet
       → StockService.move(...)
            SqlSession 열기
            출발 창고 감소 (부족이면 예외)
            도착 창고 증가
            history OUT, history IN (같은 group_no)
            commit / 실패 시 rollback
            close
       → 결과 화면 또는 리다이렉트
```

출고·출고 요청 승인도 같은 패턴이다. 해당 창고 수량이 부족하면 commit하지 않는다.

### 4.4 요청 승인

```
일반 회원 → tb_stock_request (WAIT)
관리자 승인 IN  → warehouse_stock +  / history IN  / APPROVE
관리자 승인 OUT → warehouse_stock −  / history OUT / APPROVE
                  (부족이면 실패, WAIT 유지)
관리자 거절     → REJECT, 재고 변동 없음
이후 MailSender로 요청자 안내 (실패해도 재고 커밋은 유지)
```

## 5. Filter · 세션

| Filter | URL | 동작 |
|---|---|---|
| EncodingFilter | 전체 | request/response UTF-8 |
| LoginFilter | 재고, 요청, 마이페이지, `/home`, `/admin/*` 등 | `loginMember` 없으면 `/loginFrm` |
| AdminFilter | `/admin/*` | 등급 1이 아니면 메인(또는 홈)으로 |

세션

- 키: `loginMember`
- 타임아웃: 30분
- 저장 전 `memberPw`는 null
- 가입 인증: 세션에 코드·이메일·만료시각. DB 테이블 없음

## 6. 데이터 아키텍처

```
tb_member
tb_warehouse          tb_category
        \                 /
         tb_goods (image_path 1장)
              |
    tb_warehouse_stock   ← 현재고 (창고 × 품목)
              |
    tb_stock_history     ← 실제 변동만 (IN / OUT / ADJUST)
    tb_stock_request     ← 요청만 (WAIT / APPROVE / REJECT)
```

- 품목 전체 재고 = 해당 `goods_no`의 `stock_qty` 합계
- 이동: 화면 1건, DB 2행, 동일 `group_no`
- 요청 승인 시에만 history에 `request_no`를 넣는다
- 파일은 DB에 넣지 않고 `C:/Temp/stock` 경로만 저장한다

상세는 [ERD](ERD.md).

## 8. 배포 · 실행 환경

| 항목 | 로컬 개발 | 배포 |
|---|---|---|
| JDK | 11 | 11 |
| 컨테이너 | Tomcat 9 | Tomcat 9 |
| HTTP 포트 | **8070** | **8080** |
| 산출물 | Maven war | 동일 war |
| DB | Oracle XE `localhost:1521:xe` | Oracle `호스트:1521:xe` |
| 계정 | `stock_user` | 배포 계정 (예: `aws_stock`) |
| 연결 | `db.properties` | 배포 시 URL·계정만 교체 |
| 업로드 | `C:/Temp/stock` | 서버 동일 경로 또는 설정 변경 |

로컬 앱의 `db.properties`는 localhost / `stock_user`를 유지한다.  
원격 DB에 붙일 때는 배포 설정만 바꾼다.

```
[브라우저]
    HTTP 8070 또는 8080
        [Tomcat + StockHub.war]
            JDBC ojdbc8
                [Oracle XE :1521 SID xe]
            SMTP 587
                [Gmail]
            파일
                [C:/Temp/stock]
```

## 11. 설계 원칙

1. **현재고와 요청을 분리한다.** 요청 insert만으로 수량이 변하지 않는다.
2. **변동은 이력과 같이 커밋한다.** 재고만 바뀌고 history가 없거나 그 반대이면 롤백한다.
3. **이동은 두 창고가 한 트랜잭션이다.** 출발만 줄고 도착이 안 늘면 안 된다.
4. **권한은 Filter에서 막는다.** JSP 메뉴 숨김만으로 관리자 URL을 막지 않는다.
5. **Servlet은 얇게 둔다.** 화면 이동과 JSON만. 업무 규칙은 Service.
