# StockHub 테이블 정의서

기준: Oracle XE, `sql/schema.sql`. 기획서 테이블명을 `tb_` + snake_case로 구현했다.

| 기획서 | 실제 테이블 |
|---|---|
| member_tbl | tb_member |
| warehouse_tbl | tb_warehouse |
| category | tb_category |
| goods_tbl | tb_goods |
| warehouse_stock | tb_warehouse_stock |
| stock_request | tb_stock_request |
| stock_history | tb_stock_history |

---

## 1. tb_member (회원)

가입 기본 등급 3(일반). 관리자(1)는 관리자 화면에서만 지정한다.  
비밀번호는 BCrypt. 세션 `loginMember`에는 `memberPw`를 넣지 않는다.

| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
|---|---|---|---|---|
| member_no | NUMBER | PK | seq_member | 회원 번호 |
| member_id | VARCHAR2(20) | NOT NULL, UNIQUE | | 로그인 아이디 |
| member_pw | VARCHAR2(100) | NOT NULL | | BCrypt 해시 |
| member_name | VARCHAR2(50) | NOT NULL | | 이름 |
| member_phone | VARCHAR2(20) | | | 전화번호 |
| member_addr | VARCHAR2(200) | | | 주소 |
| member_email | VARCHAR2(100) | | | 가입 인증 메일. 수정 불가 |
| member_level | NUMBER | NOT NULL | 3 | 1 관리자 / 3 일반 |
| enroll_date | DATE | | SYSDATE | 가입일 |

## 4. tb_goods (품목)

안전재고(`safety_qty`)는 **전 창고 합계** 기준이다.  
대표 이미지 1장만 `image_path`에 두고, 파일은 `C:/Temp/stock`에 둔다. 첨부파일 테이블은 없다.

| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
|---|---|---|---|---|
| goods_no | NUMBER | PK | seq_goods | 품목 번호 |
| goods_code | VARCHAR2(30) | NOT NULL, UNIQUE | | 품목코드. 바코드·검색 |
| goods_name | VARCHAR2(100) | NOT NULL | | 품목명 |
| category_no | NUMBER | FK → tb_category | | 분류 |
| unit | VARCHAR2(20) | | | 개, 박스 등 |
| safety_qty | NUMBER | | 0 | 안전재고 (전 창고 합계) |
| unit_price | NUMBER | | | 단가 |
| image_path | VARCHAR2(300) | | | 대표 이미지 경로 |
| use_yn | CHAR(1) | NOT NULL | Y | Y 사용 / N 중지 |

**FK:** `fk_goods_category` (`category_no` → `tb_category.category_no`)

## 5. tb_warehouse_stock (창고별 현재고)

재고의 **기준 테이블**. 품목 전체 수량 = 이 테이블 `stock_qty` 합계.

예: (본사창고, 노트북) 30 + (매장창고, 노트북) 15 → 노트북 전체 45.

| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
|---|---|---|---|---|
| warehouse_no | NUMBER | PK, FK | | 창고 |
| goods_no | NUMBER | PK, FK | | 품목 |
| stock_qty | NUMBER | NOT NULL, CHECK ≥ 0 | 0 | 해당 창고 현재 수량 |

**PK:** `(warehouse_no, goods_no)`  
**FK:** `fk_ws_warehouse`, `fk_ws_goods`  
**CK:** `ck_stock_qty` (`stock_qty >= 0`)

## 6. tb_stock_request (입고·출고 요청)

일반 회원이 올린 요청. **재고는 이 테이블에서 바꾸지 않는다.**  
승인 시에만 `tb_warehouse_stock`과 `tb_stock_history`가 변한다.

| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
|---|---|---|---|---|
| request_no | NUMBER | PK | seq_request | 요청 번호 |
| member_id | VARCHAR2(20) | NOT NULL | | 요청자 아이디 |
| warehouse_no | NUMBER | NOT NULL, FK | | 입고 또는 출고 창고 |
| goods_no | NUMBER | NOT NULL, FK | | 품목 |
| qty | NUMBER | NOT NULL | | 요청 수량 |
| request_type | VARCHAR2(20) | NOT NULL | | IN 입고 / OUT 출고 |
| status | VARCHAR2(20) | NOT NULL | | WAIT / APPROVE / REJECT / CANCEL |
| memo | VARCHAR2(500) | | | 메모 |
| request_date | DATE | | SYSDATE | 요청 일시 |
| process_date | DATE | | | 처리 일시 |
| process_member_id | VARCHAR2(20) | | | 승인자 아이디 |

**FK:** `fk_sr_warehouse`, `fk_sr_goods`  
`member_id` / `process_member_id`는 DDL FK가 아니다. 탈퇴 후에도 요청 행을 남긴다.

### 상태

| status | 의미 | 재고 |
|---|---|---|
| WAIT | 대기 | 변동 없음 |
| APPROVE | 승인 | IN이면 +, OUT이면 − (부족하면 실패, WAIT 유지) |
| REJECT | 거절 | 변동 없음 |
| CANCEL | 본인 취소 | 변동 없음. WAIT만 가능 |

## 7. tb_stock_history (입출고 이력)

실제로 재고가 변한 기록만 넣는다. `history_type`은 `IN` / `OUT` / `ADJUST`만.

| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
|---|---|---|---|---|
| history_no | NUMBER | PK | seq_history | 이력 번호 |
| group_no | NUMBER | NOT NULL | seq_group | 한 작업을 묶는 번호. 이동은 두 행이 같음 |
| history_type | VARCHAR2(20) | NOT NULL | | IN / OUT / ADJUST |
| warehouse_no | NUMBER | NOT NULL, FK | | 이 행의 before/after 창고 |
| goods_no | NUMBER | NOT NULL, FK | | 품목 |
| qty | NUMBER | NOT NULL | | 변동 수량 |
| before_qty | NUMBER | | | 변동 전 해당 창고 수량 |
| after_qty | NUMBER | | | 변동 후 해당 창고 수량 |
| member_id | VARCHAR2(20) | | | 처리자 |
| request_no | NUMBER | FK | | 요청 승인이면 요청 번호, 아니면 null |
| memo | VARCHAR2(500) | | | 메모 |
| history_date | DATE | | SYSDATE | 처리 일시 |

**FK:** `fk_sh_warehouse`, `fk_sh_goods`, `fk_sh_request`

### 이력 규칙

| 작업 | history | 비고 |
|---|---|---|
| 입고 IN | 1행 IN | 해당 창고 +. 요청 승인이면 `request_no` |
| 출고 OUT | 1행 OUT | 해당 창고 수량 ≥ qty일 때만 − |
| 조정 ADJUST | 1행 ADJUST | 한 창고 수량을 목표값으로 |
| 이동 | 2행 OUT+IN | 같은 `group_no`, 한 트랜잭션. 출발 부족이면 전체 롤백 |

이동 예: A→B 5개, A before=30 after=25, B before=10 after=15.

## 8. 인덱스 · 제약 요약

PK·UNIQUE는 위 표와 같다. 별도 인덱스 스크립트는 없다. Oracle이 PK/UK에 인덱스를 만든다.

| 제약 이름 | 테이블 | 내용 |
|---|---|---|
| fk_goods_category | tb_goods | category_no → tb_category |
| pk_warehouse_stock | tb_warehouse_stock | (warehouse_no, goods_no) |
| ck_stock_qty | tb_warehouse_stock | stock_qty ≥ 0 |
| fk_ws_warehouse | tb_warehouse_stock | warehouse_no → tb_warehouse |
| fk_ws_goods | tb_warehouse_stock | goods_no → tb_goods |
| fk_sr_warehouse | tb_stock_request | warehouse_no → tb_warehouse |
| fk_sr_goods | tb_stock_request | goods_no → tb_goods |
| fk_sh_warehouse | tb_stock_history | warehouse_no → tb_warehouse |
| fk_sh_goods | tb_stock_history | goods_no → tb_goods |
| fk_sh_request | tb_stock_history | request_no → tb_stock_request |

관계 그림은 [ERD](ERD.md).
