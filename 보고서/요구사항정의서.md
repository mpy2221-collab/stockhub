# StockHub 요구사항 정의서

기준: [기획서](기획서.md)와 구현된 화면·Service.  
데이터 구조는 [ERD](ERD.md), [테이블 정의서](테이블정의서.md)를 따른다.  
화면·처리 상세는 [기능 명세서](기능명세서.md)를 따른다.

우선순위: **필수**는 없으면 시스템을 쓸 수 없는 항목, **권장**은 운영 편의 항목이다.

## 1. 기능 요구사항

### 1.1 회원 · 인증

| 요구사항 | 우선 | 설명 |
|---|---|---|
| 회원가입 | 필수 | 아이디·비밀번호·이름·이메일 필수. 기본 등급 3(일반) |
| 이메일 인증 | 필수 | 인증번호 6자리를 메일로 보내고 확인한 뒤에만 가입. 세션 만료 5분. 인증 테이블 없음 |
| 아이디 중복 확인 | 필수 | Ajax. 중복이면 가입 불가 |
| 이메일 중복 확인 | 필수 | Ajax. 이미 쓴 이메일은 인증 발송 불가 |
| 로그인 | 필수 | 아이디·비밀번호. BCrypt 검증. 성공 시 세션 `loginMember`, 비밀번호는 세션에 넣지 않음 |
| 로그아웃 | 필수 | 세션 종료 |
| 비밀번호 찾기 | 필수 | 아이디+이메일이 맞으면 임시 비밀번호를 저장하고 메일 |
| 마이페이지 조회 | 필수 | 본인 정보 확인 |
| 회원 정보 수정 | 필수 | 이름·전화·주소. 아이디·이메일은 수정 불가 |
| 비밀번호 변경 | 필수 | 현재 비밀번호 확인 후 변경 |
| 회원 탈퇴 | 필수 | 현재 비밀번호 확인 후 행 삭제. 마지막 관리자는 불가. 성공 시 세션 종료 |
| 로그인 가드 | 필수 | 비로그인은 재고·요청·마이페이지·관리자 화면에 못 들어간다. 첫 화면은 로그인 |
| 관리자 가드 | 필수 | `/admin/*`는 등급 1만 |

### 1.2 재고 조회

| 요구사항 | 우선 | 설명 |
|---|---|---|
| 재고 목록 | 필수 | 로그인 회원. 품목코드·품목명·카테고리·창고·키워드·부족 필터 |
| 품목 상세 | 필수 | 대표 이미지, 전 창고 합계, 창고별 수량, 안전재고 |
| 바코드 | 권장 | 품목코드(`goods_code`)를 JsBarcode로 표시 |
| 안전재고 미달 | 필수 | 전 창고 합계가 `safety_qty` 미만인 품목 |

### 1.3 입고·출고 요청 (일반 회원)

| 요구사항 | 우선 | 설명 |
|---|---|---|
| 입고·출고 요청 | 필수 | 창고·품목·수량·유형(IN/OUT)·메모. 상태 WAIT |
| 요청만 저장 | 필수 | `tb_stock_request`에만 넣고 재고는 바꾸지 않음 |
| 내 요청 목록 | 필수 | 본인 요청만. 상태 확인 |
| 관리자 요청 메뉴 제외 | 필수 | 관리자 회원 사이드바에 입출고 요청·내 요청을 두지 않음 |

### 1.4 관리자 기준 정보

| 요구사항 | 우선 | 설명 |
|---|---|---|
| 창고 CRUD | 필수 | 이름, 사용여부. 사용중인 창고만 입출고 대상 |
| 카테고리 CRUD | 필수 | 이름 중복 불가, 사용여부. 품목 등록 select 대상 |
| 품목 CRUD | 필수 | 코드 고유, 카테고리, 단위, 안전재고, 단가, 사용여부 |
| 품목 대표 이미지 | 권장 | 1장. `image_path` + `C:/Temp/stock`. 첨부 테이블 없음 |
| 회원 목록·등급 | 필수 | 관리자만 등급 지정. 마지막 관리자는 일반으로 내릴 수 없음 |

### 1.5 관리자 재고 처리

| 요구사항 | 우선 | 설명 |
|---|---|---|
| 입고 | 필수 | 해당 창고 +. history IN 1행. 한 트랜잭션 |
| 출고 | 필수 | 해당 창고 수량 ≥ qty일 때만 −. history OUT 1행. 부족이면 실패 |
| 창고 이동 | 필수 | 화면 1건, DB OUT+IN 2행, 같은 `group_no`, 한 트랜잭션. 출발 부족이면 전체 롤백 |
| 재고 조정 | 필수 | 한 창고 수량을 목표값으로. history ADJUST 1행 |
| 입출고 이력 | 필수 | 유형·기간·품목·창고 조회. 이동은 같은 `group_no`로 묶여 보임 |
| 이력 유형 제한 | 필수 | `history_type`은 IN / OUT / ADJUST만 |

### 1.6 요청 승인

| 요구사항 | 우선 | 설명 |
|---|---|---|
| 요청 목록 | 필수 | 상태 필터. 기본 탭은 대기(WAIT) |
| 입고 승인 | 필수 | WAIT만. 재고 증가 + history IN + `request_no`. 상태 APPROVE |
| 출고 승인 | 필수 | WAIT만. 재고 감소 + history OUT + `request_no`. 부족이면 실패, WAIT 유지 |
| 거절 | 필수 | WAIT만. 상태 REJECT. 재고 유지 |
| 처리 안내 메일 | 권장 | 승인·거절 후 요청자 이메일. 메일 실패는 처리를 되돌리지 않음 |
| 요청 상세 | 권장 | 목록 행 클릭 시 메모·처리 정보 모달 |

### 1.7 현황 · 홈 · 엑셀

| 요구사항 | 우선 | 설명 |
|---|---|---|
| 대시보드 카드 | 필수 | 품목·창고·카테고리·회원, 총 재고, 안전재고 미달, 오늘/이번달 입출고, 대기 요청 |
| 대시보드 차트 | 권장 | 월별 입출고 추이, 창고별 재고, 카테고리 비율, 출고 상위 품목. Ajax JSON |
| 대시보드 표 | 필수 | 미달 목록, 최근 이력, 대기 요청 |
| 메인 홈 | 필수 | 로그인 후 포털. 요약 카드, 바로가기, 최근 내 요청, 미달 목록 |
| 엑셀 다운로드 | 권장 | 기간별 입출고 이력. Apache POI |
| 레이아웃 | 필수 | 슬림 헤더 + 회원/관리자 사이드바. 960px 미만 햄버거 서랍 |

## 2. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 아키텍처 | Spring 없음. Servlet → Service → Dao(MyBatis) → Oracle |
| 트랜잭션 | 재고 변경은 한 SqlSession. 실패 시 rollback |
| 보안 | 비밀번호 BCrypt. 세션 30분. EncodingFilter UTF-8 |
| 권한 | LoginFilter / AdminFilter. 화면에서만 가리지 않음 |
| 인코딩 | UTF-8. SQL은 `#{}`만 |
| 테스트 | Service 단위 테스트 JUnit 5 + Mockito. Dao는 Mock |
| 이식 | 로컬 Tomcat 8070, 배포 Tomcat 8080. DB 연결은 설정 파일 |
| 파일 | 업로드 경로 `C:/Temp/stock`. 대표 이미지 1장 |
| 메일 | JavaMail + Gmail SMTP(587, STARTTLS). Spring 메일 설정 키 사용 금지 |
| UI | 들여쓰기·코드 스타일은 프로젝트 규칙. 화면은 EL·JSTL, 스크립틀릿 최소화 |
| 반응형 | 960px 미만에서 메뉴·표가 깨지지 않을 것. 표는 nowrap + 가로 스크롤 |

## 4. 업무 규칙 (요약)

1. 재고 기준은 창고×품목이다. 품목 전체 수량 = 창고 합계.
2. 요청 테이블에서 재고를 직접 바꾸지 않는다.
3. 출고·출고 승인은 해당 창고 수량이 부족하면 실패한다.
4. 이동은 출발과 도착이 모두 성공해야 커밋한다.
5. 안전재고는 전 창고 합계와 비교한다.
6. 가입 기본 등급은 3이다. 관리자 지정은 관리자 화면에서만 한다.
