# StockHub

사내·매장 창고의 **현재고**와 **입출고**를 관리하는 웹 시스템입니다.  
Spring 없이 Servlet 4.0 + JSP + MyBatis로 구현했습니다.

재고의 기준은 **창고 × 품목**입니다. 품목 전체 수량은 창고 합계입니다.  
일반 회원은 입고·출고를 **요청**만 하고, 실제 수량은 관리자 승인 후에만 바뀝니다.

## 주요 기능

- 회원가입(이메일 인증), 로그인, 마이페이지, 비밀번호 찾기
- 재고 조회, 품목 상세, 바코드
- 일반 회원: 입고·출고 요청, 내 요청
- 관리자: 품목·창고·카테고리·회원 관리
- 입고, 출고, 창고 이동, 재고 조정, 입출고 이력
- 요청 승인·거절 (출고 부족이면 실패, 대기 유지)
- 대시보드(카드·차트·표), 입출고 엑셀 다운로드

## 개발 도구

코드·문서의 설계와 구현은 직접 하고, **Cursor AI**는 보조로만 썼습니다.  
**MCP(Model Context Protocol)**는 적극적으로 활용했습니다. GitHub, Playwright 등 외부 도구를 편집기에 붙여 저장소 작업과 화면 확인을 이어서 처리했습니다.

| MCP | 용도 |
| --- | --- |
| GitHub | 브랜치, 커밋, Pull Request, 머지 |
| Playwright | 브라우저에서 화면·동작 확인 |
| Sequential Thinking | 요구사항·재고 규칙을 단계별로 정리 |
| Notion Toolbox | 기획·보고서 초안과 작업 기록 |
| Context7 | 라이브러리·API 문서 조회 |

## 데모 계정

비밀번호는 모두 `1234`입니다.

| 구분 | 아이디 | 비밀번호 |
| --- | --- | --- |
| 관리자 | `admin1`, `admin2`, `admin3` | `1234` |
| 일반 회원 | `user01` ~ `user20` | `1234` |

화면 헤더의 **안내** 버튼에서도 같은 계정을 확인할 수 있습니다.

## 이용 가이드

1. **안내·회원가입·로그인**  
   상단 **안내**에서 프로젝트 소개와 테스트 계정을 볼 수 있습니다.  
   회원가입은 아이디, 비밀번호, 이름, 전화번호, 주소, 이메일을 넣고 이메일 인증 후 완료됩니다.  
   로그인하면 서비스를 이용할 수 있고, 비밀번호 찾기는 이메일로 임시 비밀번호를 보냅니다.

2. **홈**  
   로그인 후 홈에서 재고 조회, 입출고 요청, 마이페이지로 들어갑니다.  
   관리자는 재고 현황 대시보드로 바로 갈 수 있습니다.  
   화면이 좁으면 햄버거 메뉴로 같은 항목을 엽니다.

3. **재고 조회**  
   품목코드·품목명으로 검색하고, 카테고리·창고로 걸러 볼 수 있습니다.  
   품목을 누르면 상세(이미지, 창고별 수량, 바코드)가 나옵니다.  
   안전재고보다 적은 품목은 강조되어 보입니다.

4. **입출고 요청**  
   일반 회원은 창고·품목·수량을 골라 입고 또는 출고를 **요청**합니다.  
   이 단계에서는 재고가 바로 바뀌지 않습니다.  
   내 요청에서 대기 건을 취소할 수 있습니다.

5. **요청 승인**  
   관리자가 대기 요청을 승인하면 입고는 수량 증가, 출고는 수량 감소와 이력이 남습니다.  
   거절하면 재고는 그대로입니다.  
   출고 승인은 해당 창고 재고가 부족하면 실패하고, 요청은 대기로 남습니다.

6. **마이페이지**  
   이름, 전화번호, 주소, 이메일을 수정하고 비밀번호를 바꿀 수 있습니다.  
   탈퇴하면 계정은 삭제되고, 입출고 이력은 남습니다.

7. **관리자**  
   `admin1`로 로그인하면 헤더에 관리자페이지가 보입니다.  
   재고 현황, 품목·창고·카테고리·회원 관리, 입고·출고·이동·조정, 입출고 이력, 요청 승인, 엑셀 다운로드를 합니다.
